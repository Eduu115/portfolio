API Arena

A platform that grades REST APIs built by students, automatically and for real. I designed it, built it alone and run it in production.

What it does

A student picks a challenge and submits a Spring Boot project. API Arena builds it, runs it in its own isolated container, fires real HTTP requests at it, measures how it performs, reviews the code and puts the score on a live leaderboard.

No mocked answers: the API under test is real, and so are the requests.

How a submission is scored

  • 300Functional HTTP tests
  • 300Performance
  • 200REST design
  • 200Code review

Maximum score: 1,000 points.

The sandbox fails

If Docker-in-Docker cannot start, sandbox-service switches to its fallback runner. The project is still built, run and graded, and the rest of the pipeline never notices.

Two bugs I found and fixed

Events were disappearing

symptom
Some Kafka events never got processed, and nothing reported it.
cause
Consumers caught exceptions and swallowed them, so a failed event looked handled.
fix
Failures now surface: retries with exponential backoff (1, 2, 4, 8 s), then a dead-letter topic per consumer group. Malformed JSON goes straight to the DLT. Every failed event is kept and can be inspected.
lesson
Failures have to be visible and kept, never silently dropped.

The sandbox could stop grading

symptom
When the Docker-in-Docker sandbox failed, submissions could not be graded.
cause
Grading depended on a single execution path.
fix
An automatic fallback runner takes over when DinD fails, so the pipeline keeps grading.
lesson
A critical dependency needs a fallback before it breaks.
